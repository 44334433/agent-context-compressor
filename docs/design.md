# 双支路架构设计

## 为什么单支路必然失忆

纯压缩型（摘要/提炼任一单独）在长程召回上已被基准实证打穿：AgentMemBench (arXiv 2608.00009) 实测 491 标注问句下纯摘要型 Recall@5≈0.005，只有稠密向量检索能 scale (0.573)。滚动式摘要的「telephone game」缺陷（反复折叠模糊细节）使它成为失忆的镜像而非解药。

## 双支路盲区互补

- 摘要是**有损信道**（叙事化必然模糊细节）
- 提炼账本是**无损锚点**（机械保真）
- 两支路**各自从原文一次成型、禁互相压缩**——摘要丢的细节被账本兜住，账本碎片化的因果被叙事串起

## 生命周期层（遗忘系统）

中间层条目带 born_turn/hits/强度，幂律衰减 `1/(1+d/τ)^0.35`，状态机 ACTIVE→CONSOLIDATED→GIST→ARCHIVED（归档可回查）。**蔡格尼克免疫**：未完成项（open_loop=1）机械免疫一切衰减——防止「拍板了没执行的事」被压缩遗忘。

## 判别头：机械配对的长尾补丁

决策链机械配对（指令→动作→结果）兜底 80%；歧义窗口（一个动作多条候选指令）由 mmBERT-base 判别头 rerank（:8767 HTTP 服务，1.5s 超时 fail-open 回退最近一条）。

## 验收闸：优化指标与痛点的对齐

压缩率/速度/成本达标 ≠ 保真达标（Goodhart）。验收闸把「保真」变成常设机械检查：路径覆盖/数字覆盖/指令实录/决策链完整性，任何一项不达标即拦下并回退。

## 审计者自动化

系统的可靠性不应建在用户的警觉上。audit_ledger 记录两类事件：用户抓到的缺陷（纠错信号词扫描）与系统自检拦到的（验收闸/看门狗/生命周期）。**自检覆盖率 = 自检抓到 / (自检+用户抓)**——它趋近 1 的过程，就是用户从审计席退出的过程。
